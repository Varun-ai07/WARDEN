# WARDEN — Submission Strategy

> **Status: supporting strategy note.** [FINAL_WARDEN.md](FINAL_WARDEN.md) is the single source of truth for the product. Official event pages, current rules, and live schedules are the only authority for external eligibility, prizes, deadlines, and submission mechanics.

## What to emphasize

Lead with WARDEN's differentiated trust model:

> WARDEN can evaluate a portfolio automatically, while each real payment is limited to one merchant and one exact amount and still requires the user's passkey approval. Continuous scheduling is the next step, not an MVP claim.

Then prove it with the evidence ledger, not with a broad “agent saved money” claim.

## Strongest submission evidence

1. One completed, evidence-backed Prava payment using a scoped mandate and visible passkey.
2. OpenAI structured policy reasoning with a strict function schema, atomic portfolio planning, and deterministic validation.
3. Duplicate-safe execution: one run/decision/attempt identity, provider idempotency, and an append-only audit trail.
4. A dashboard that makes completed, recommended, prevented, declined, expired, and failed states visually unmistakable.
5. Structured provider evidence that binds the merchant, amount, currency, status, and unique reference to each terminal claim.
6. A concise explanation of monthly-policy normalization versus annual cash authorization.
7. An honest discussion of any capability that remained recommendation-only.

## Scope discipline

Do not add integrations solely to chase tracks. The strongest submission is a reliable, truthful three-outcome story. Unsupported active-plan changes and trial cancellations remain recommendations until verified.

Operational safeguards should support the story rather than become extra demo complexity. Keep the state machine, idempotency, snapshot version, and evidence details visible in a compact “proof” drawer or developer panel, while the main user experience stays simple.

## Submission checks

- Recheck current official rules, deadline, tracks, team eligibility, and publication state directly before submission.
- Name only technologies and integrations actually used.
- Keep provider evidence available for reviewers.
- Scrub secrets, credentials, and personal data from the repository and video.
- Ensure README, pitch, UI, and spoken demo use the same outcome terminology as `FINAL_WARDEN.md`.
